# Layer 1 Seed Corpus

Each JSON program is a small Strand graph using only N-001 through N-019 plus
N-034 (TypeAbstraction) and N-035 (ForallType). The verifier performs
explicit-instantiation type checking in the System F style: a polymorphic term
is a TypeAbstraction whose type is a ForallType, and every Application of a
polymorphic value supplies a positional `typeArguments` list whose length
equals the function's quantified type-parameter count. A monomorphic call
supplies an empty `typeArguments` list (or omits the field). Partial
instantiation is rejected. Type inference is not performed.

| 01-int-literal.json | run | A bare IntLit `42`. Verifies to `Int`, evaluates to `42`. |
| 02-identity-applied.json | run | The identity `Λa. \x:a. x` applied to `42` with `typeArguments: [Int]`. |
| 03-let-identity.json | run | `let id = Λa. \x:a. x in id[Bool](true)`. |

Verifies the polymorphic type only. |
| 06-let-polymorphic.json | run | A single let-bound `id = Λa. \x:a. x` applied at two different types; each call carries its own `typeArguments`. |
| 07-higher-order.json | run | Higher-rank demonstration. The inner identity is genuinely polymorphic; its parameter type is a ForallType. This is the rank-2 example the System F refactor enables. |
| 08-product-type-decl.json | verify-only | A Lambda whose parameter is a `ProductType { a: Int, b: Bool }`; demonstrates type wiring without a product-value constructor (Layer 1 has none). |
| 09-sum-type-decl.json | verify-only | A Lambda whose parameter is a `SumType` (Option-like); demonstrates type wiring without a sum-value constructor. |
| 10-noderef-shared.json | run | Uses `NodeRef` to share a single IntLit between two Application positions; each call instantiates `id` at `Int`. |
| 11-higher-rank-apply.json | run | A minimal explicit higher-rank example: `apply : (forall a. a -> a) -> Int -> Int = \f:(forall a. a -> a). \n:Int. f[Int](n)` applied to a polymorphic identity and `7`. Evaluates to `7`. |
| 12-effect-declared-and-granted.json | run (under {Time.Now}) | A Lambda over `Int → Int` that declares `Time.Now`. | 13-capability-scope-narrow-then-call.json | run (under {Time.Now, Network.Connect}) | A `CapabilityScope` that narrows the surrounding context to `{Time.Now}` and then calls a Lambda that declares `Time.Now`. The body succeeds because the needed effect survives the narrowing. The other declared categories (`Network.Connect`) are filtered out by the scope. |
| 14-multi-effect-lambda.json | run (under {Time.Now, Network.Connect, Filesystem.Read}) | A Lambda declaring three effects, applied at `Int → Int`. The interpreter checks every declared effect against the context — all present, so the call proceeds. |
| 15-builtin-add.json | run | The first program that does real computation: a `ForeignNode` targeting the in-process `strand-builtin:Int.Add`. Pure (no declared effects); requires no capabilities. Evaluates to `5`. |
| 16-builtin-time-now-under-capability.json | run (under {Time.Now}) | A `ForeignNode` targeting `strand-builtin:Time.Now`, declaring `Time.Now` as its effect. Evaluates to the reference implementation's fixed replay timestamp under a context that grants the effect. |
| 17-builtin-compose-pure-and-effectful.json | run (under {Time.Now}) | Composes the pure builtin `Int.Add` with the effectful builtin `Time.Now`: `add(now(), 1)`. Demonstrates effect closure propagation through Application and that pure builtins can be called freely while effectful ones gate on capability. Evaluates to `replay-timestamp + 1`. |
| 18-match-int-literal-with-wildcard.json | run | A `Match` on `IntLit 0` with two cases: a literal pattern matching `0` (returns `100`) and a wildcard pattern (returns `200`). Scrutinee is `0`, so the first case wins. Evaluates to `100`. The smallest meaningful pattern-matching example: literal vs. wildcard. |
| 19-match-on-comparison-result.json | run | A `Match` on the `Bool` result of `Int.Lt(3, 5)`. Two cases pattern-match `BoolLit(true) → 1` and `BoolLit(false) → 0`. This is the canonical `if`-as-`match` idiom: branching on a comparison via two literal Bool patterns. Evaluates to `1`. |
| 20-match-variable-binding.json | run | A `Match` on `IntLit 7` with a variable pattern that binds the scrutinee to `n` for use inside the case body. The body computes `n + 10` via `Int.Add`. Demonstrates `VariablePattern` as a new binding occurrence — `VarRef.binder` points at the pattern's `NodeId`. Evaluates to `17`. |
| 21-fixpoint-factorial.json | run | The first recursive program: factorial via `Fixpoint` + `Match` + comparison/arithmetic builtins. `fact(0) = 1`; otherwise `fact(n) = n * fact(n-1)`. The body Lambda's first parameter is the recursive call slot, supplied at runtime by the `Fixpoint`. Applied to `5` → `120`. |
| 22-fixpoint-sum-to-n.json | run | Sum of 1..N via `Fixpoint` + `Match`. `sum(n) = 0` if `n <= 0`, else `n + sum(n-1)`. Pairs `Int.Le` for termination with `Int.Add` and `Int.Sub` for the inductive step. Applied to `10` → `55`. |
| 23-product-construct-and-access.json | run | Construct a `{x: 3, y: 4}` point via `ProductValue` and read field `y` with `ProductFieldGet`. The smallest end-to-end product example: closes the long-standing gap where product types could be declared but not instantiated. Evaluates to `4`. |
| 24-product-sum-fields-via-lambda.json | run | A function over the same `Point` type that reads both fields and sums them. Demonstrates that `ProductValue`s flow normally through `Application` boundaries and that field-access composes with arithmetic. Applied to `{x: 10, y: 32}` → `42`. |
| 25-option-some-unwrap.json | run | Option-like sum (`Some(Int)` / `None`). Construct `Some(42)`, `Match` with constructor patterns binding the payload; the `Some(n) → n` case returns `42`. |
| 26-option-none-default.json | run | Same Option type as 25; this time the constructed value is `None`, so the `Some(n)` pattern fails and the `None → -1` case wins. Demonstrates the no-payload constructor pattern. |
| 27-result-ok-or-err.json | run | Result-like sum (`Ok(Int)` / `Err(String)`). Construct `Ok(7)`, `Match` with two constructor patterns of different payload types. The `Ok(n) → n + 100` case wins; `Err(_) → -1` would handle the error path. Evaluates to `107`. |
| 28-safe-divide-success.json | run | The first program combining the full vocabulary: a `safe-divide` Lambda returns `Option<Int>` (`None` on zero divisor, `Some(n/d)` otherwise) via `Match` on the `Int.Eq` comparison. | 29-safe-divide-by-zero.json | run | Same `safe-divide` function as 28 but applied to `divide(10, 0)` → `None` → falls back to `-1`. Together with 28, demonstrates both code paths and the Option-returning idiom for fallible operations. |
| 30-string-concat.json | run | Minimal `String.Concat` builtin demo: `"Hello, " + "Strand!"` → `"Hello, Strand!"`. Smallest program with a non-Int / non-Bool result. |
| 31-recursive-list-head.json | run | First program over a recursive type. Defines `List = μ. Nil | Cons(head: Int, tail: List)` via `RecursiveType` + `RecursiveSelf`. | 32-recursive-list-sum.json | run | The capstone: sum the elements of a recursive linked list `[1, 2, 3]` via `Fixpoint` + `Match` over the recursive sum type. Demonstrates the full language vocabulary in a single program — recursive types, sum constructors, product field access, pattern matching with variable binding, fixed-point recursion, and foreign builtin arithmetic. Result: `6`. |
| 33-refined-network-connect.json | run (under `Network.Connect{host: "api.example.com", port: 443}`) | Q-031 step one: `Network.Connect(api.example.com, 443)` with an `Application.effectInstances` entry whose EffectDecl parameters are the host and port arguments. State-machine programs ship paired with `<id>-...events.json` event-list files for the `strand machine` CLI subcommand. The event-list JSON schema is documented in `runtime/EventCodec.kt`.

Two TypeParameter nodes are the same type variable when they are the same
node; consequently programs 07 and 11 share a single `T_a` node between the
ForallType that classifies the higher-rank parameter and the TypeAbstraction
that produces the polymorphic argument. Layer 1 compares Forall types by
structural equality on their NodeId-keyed bindings; Layer 2's canonical
encoding will perform the alpha-equivalence normalization that lifts this
sharing requirement.
